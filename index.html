About

Building the pipeline, not just watching it run

I'm Arman, and I'm building my DevOps skills the same way I'd build a pipeline: one stage at a time, in public, where every failed build is visible and every fix is documented. Right now that means getting hands-on with Docker, CI/CD via GitLab, and GitHub Actions — using this site itself as the test bed for every new tool I pick up.

I'm less interested in collecting tool names and more interested in understanding the full path a commit takes to become something running safely in production.
